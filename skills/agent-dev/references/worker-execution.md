# Worker Execution

Read this reference only when coordinated or staged delivery is considering a clean-context implementation or verification worker.

Use one worker only for an enforceable safety or capability boundary, fresh independent judgement required by assurance, or a supported whole-task context benefit for a self-contained noisy packet. File count, parallelism, or presumed token savings is not enough.

Start from a baseline containing every accepted dependency. Use actual worktree isolation and tool or permission limits when available. Give the worker one bounded result, current evidence, allowed paths and mutations, required checks, and a compact return. It must not mutate the owning record, tracker, unrelated files, commits, or remote state, and it must return its changed files, concise approach, checks and results, missing evidence, and any decision or stop signal.

The main owner retains scope, user decisions, shared state, packet assignment, integration, final verification, commits, and communication. Inspect the complete returned diff, accept only change-owned work, reconcile it with the current revision, and rerun its narrow checks before marking the packet complete. If the boundary cannot be enforced, work inline only when that remains safe; otherwise keep the work unresolved and name the missing capability.

Use another worker only for a second independent uncertainty. Never delegate overall delivery coordination or duplicate the full worker task inline without a concrete reason.
