# Write or Revise

Create a complete audience-ready result or apply only the findings the user accepted.

## Select the writing type

Read exactly one reference.

| Result | Read |
| --- | --- |
| Email, report, memo, briefing, proposal, article, announcement, communication, or risk or decision write-up | [Practical writing](../references/practical-writing.md) |
| Guide, tutorial, how-to, runbook, API document, reference, integration guide, or other complete technical document | [Technical document](../references/technical-document.md) |
| Explanation of a technical concept, API, behaviour, or system | [Technical explanation](../references/technical-explanation.md) |

Infer the type from the requested artifact and reader task. A technical document may contain explanatory sections without loading the explanation reference. If the result is genuinely ambiguous and the choice would materially change the artifact, ask one short question.

## Writing contract

Identify the audience, purpose, desired response or success condition, source material, and any format, length, scope, or placement constraint. Ask only when a missing answer would materially change the writing. For revision, preserve sound material and intentional voice; do not change claims or scope without authority.

When applying review or correctness findings, apply only those the user accepted. Leave rejected or undecided points unchanged and do not imply that revision itself supplies fresh review evidence.

## Finish

Check the complete result against the reader's task and sources. Confirm that the opening or orientation works, terms stay consistent, claims are grounded, evidence and recommendation are distinguishable, and the reader can tell what happens next. Remove placeholders and state material evidence limits.
