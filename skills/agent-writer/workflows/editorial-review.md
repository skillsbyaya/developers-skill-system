# Editorial Review

Review existing writing for its intended reader. Diagnose the few changes that would most improve what the reader understands, trusts, decides, or does.

## Select the review lens

Read exactly one reference.

| Artifact | Read |
| --- | --- |
| Practical audience-facing nonfiction | [Practical-writing review](../references/practical-writing-review.md) |
| Guide, tutorial, runbook, API document, reference, or other technical documentation | [Technical-document review](../references/technical-document-review.md) |

Read the specified artifact fully and any supplied style or documentation standard. Identify or infer the audience, purpose, desired response or task, constraints, and success condition. Ask one concise question only when a missing answer would materially change the review; otherwise state the assumption.

## Report contract

Lead with a one-sentence readiness assessment. Then report findings in priority order with `high`, `medium`, or `low`, the location, likely reader impact, and the smallest useful direction. Use `high` only when the issue could change meaning, trust, decision quality, task success, or the ability to act.

Combine repeated instances, quote only enough to locate the issue, and say the writing is ready when no consequential problem remains. Preserve the writer's facts, intent, uncertainty, terminology, voice, and fixed choices; query ambiguity rather than resolving it by invention.

End with the smallest next step and ask whether the user wants accepted findings applied through write or revise. Do not edit before confirmation.
