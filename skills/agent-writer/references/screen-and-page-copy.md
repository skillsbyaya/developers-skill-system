# Screen and Page Copy

Use for words people read on a screen: labels, buttons, headings, messages and empty states in an interface, and the prose of a public web page. A project's own copy rules take precedence where they are stricter.

## Words in an interface

The default is no explanatory text. Apply `agent-ux-designer`'s Interface copy reference to every string: ask what the user cannot act on without it, fix the label before adding a line to explain it, and cut what restates the heading, the options or the state of the page. Name things in the user's own words, and say what a control will do.

## Prose on a public page

Write as the people behind the product would speak to one reader. Use the facts and the voice the user has given; a specific true detail carries more than a claim.

Read the draft aloud and rewrite any line that sounds written by a machine. The usual signs:

- a neat tagline closing a paragraph ("Nobody bakes from an old copy.");
- a headline-style title where a plain name would do ("Christmas, remembered" for "Christmas and Easter");
- a story with no person in it ("It started in a working bakery") where "we" or "our" is true;
- three-part lists and matched pairs used for rhythm, not because there are three things;
- claims of ease, power or transformation in place of what actually happens.

Keep it short. Cut any sentence the page works without.

Finish by reading every string in place on the rendered screen, not in the source: wording that reads well in a file can be too long, repeated or out of order on the page.
