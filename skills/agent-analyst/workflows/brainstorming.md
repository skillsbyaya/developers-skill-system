# Brainstorming

Use this workflow when the primary need is divergent option generation. Do not use it to validate one chosen idea, diagnose a known operational problem, or improve existing prose.

## Set the creative frame

Establish the challenge, intended beneficiary or stakeholder, useful constraints, and what kind of variety would help. Treat constraints as creative material, not reasons to narrow prematurely. Infer a compact session when the user wants a quick burst; use a deeper interactive session when they want broad exploration. Let the user change pace at any time. If earlier notes or a partial session exist, continue from their current question, useful ideas, and unexplored directions rather than restarting.

Choose the lightest technique that will produce meaningfully different options:

- **Open expansion:** many distinct answers to a broad question;
- **Perspective shift:** generate from different stakeholder, time-horizon, or operating-context views;
- **Constraint change:** remove, invert, tighten, or exaggerate one constraint;
- **Analogy and combination:** borrow a mechanism from another domain or combine promising fragments;
- **Failure reversal:** imagine how to cause the unwanted result, then reverse the strongest mechanisms.

The user may name a technique, ask to browse approaches, request a random technique, or delegate the choice. Useful named options include yes-and building, question storming, SCAMPER, Six Thinking Hats, analogy, random stimulus, reversal, assumption busting, first principles, morphological combinations, role perspectives, and constraint shifts. Present a small relevant shortlist with reasons only when choice would help; otherwise select one and name it briefly. Use one technique unless ideas become repetitive or the user wants a deeper session.

## Diverge, then organise

Facilitate genuine back-and-forth: invite the user's ideas, add concrete possibilities, build on promising fragments, and follow useful creative energy without turning the session into a questionnaire. Generate non-duplicate possibilities and deliberately shift to an orthogonal stakeholder, mechanism, constraint, time horizon, or domain when ideas begin clustering. During divergence, develop ideas before judging them and clearly label invented possibilities rather than implying evidence.

After enough variety exists, organise ideas by a decision-relevant pattern such as stakeholder, mechanism, effort, uncertainty, or time horizon. Invite the user to add, combine, discard, or explore ideas. Narrow only when requested or when a shortlist is necessary to answer the original goal; explain the criteria used.

## Finish or continue

In chat, return the creative frame, technique, organised ideas, promising combinations, and open directions. For a durable session requested by the user, record:

1. challenge, stakeholders, and constraints;
2. technique or techniques used;
3. generated ideas grouped without losing distinct options;
4. user selections, combinations, and discarded directions;
5. evidence gaps and next exploration.

Preserve enough context that a later session can resume without repeating completed generation.
