# Forge an Idea

Use this workflow when one idea already exists and the user wants to interrogate, strengthen, reshape, or reject it. The goal is a decision, not automatic approval.

## Establish the candidate

Restate the idea, intended beneficiary, promised change, important constraints, and the decision the user wants to reach. Infer whether the desired pressure is to harden it, prove or kill it, or think it through; ask only when the distinction would change the interrogation. Distinguish what is fixed from what may change. If a prior session exists, continue from its locked choices, unresolved assumptions, killed alternatives, and next test.

## Interrogate adaptively

Ask one consequential question at a time. Put a provisional answer, hypothesis, or decision test on the table when it gives the user something concrete to challenge. Find discoverable facts when they matter; ask the user for private context, judgement, preference, or a decision only when it changes the branch. Choose the next question from the weakest or most decision-relevant area:

- problem and stakeholder evidence;
- value, differentiation, and credible alternatives;
- incentives, adoption, and who bears cost or risk;
- operating mechanism, dependencies, and feasibility;
- failure modes, reversibility, and second-order effects;
- assumptions that can be tested cheaply.

Use evidence-driven lenses only when they expose a genuinely different uncertainty. Do not perform a scripted tour of every category. Challenge answers directly, explain why a weak point matters, and update the emerging model as the user responds.

Converge when additional questioning would not change the decision. Use one honest outcome:

- proceed under stated conditions;
- run a named test or gather missing evidence;
- reshape the idea around a stronger premise;
- pause because a material uncertainty is unresolved; or
- stop because the idea does not justify further effort.

## Finish or preserve continuity

Return the decision and the reasoning that earned it. Include the validated or still-assumed premise, locked choices, stakeholder consequences, material risks, rejected alternatives, conditions, and smallest useful next test.

If a durable summary was requested, record the idea, locks, conditions, killed alternatives, unresolved evidence, and next test; do not create a downstream brief, requirements document, or implementation plan unless separately requested.
