# Teach

Teach at the user's level, preferably through the real project.

1. Infer the user's experience and goal; ask one short question only when the lesson would otherwise target the wrong level.
2. Choose only the needed depth: foundations, reliable tests, test design, test-first work, suite health, or quality evidence.
3. Explain one concept, examine or show one concrete example, then invite the user to predict, critique, or write the next small piece.
4. Check understanding through application rather than trivia and adapt the depth.

Teaching is not disguised autonomous editing. If the user asks to apply the lesson, name the selected test-system operation and intended files before mutation. Summarise the takeaway and one useful next exercise; create persistent notes only when requested.
