# Improve

Use this operation for several interacting weaknesses, not as permission to rewrite every test.

1. Inspect the relevant framework, commands, levels, execution state, reliability, coverage gaps, and maintenance costs, then select a scope from risk, recent change, recurring pain, or explicit user priority.
2. Rank infrastructure, reliability, relevance, missing coverage, speed, and maintainability weaknesses. Separate evidence from inference.
3. Choose a small first tranche from the signal gained, cost, and risk, and continue without another confirmation when it stays within an already authorised improvement outcome. Ask again before deletion, or when a dependency change or broad rewrite is materially different or introduces a consequential trade-off the user has not already authorised.
4. Apply only the needed operations one at a time: initialize missing prerequisites, repair untrustworthy execution, address review findings within the authorised scope, then add the highest-risk missing coverage.
5. Re-run the relevant suite and compare the result with the specific baseline weaknesses. Stop when the agreed outcome is met and return remaining opportunities without expanding scope.

Prefer observable improvement such as removed reproducible flakes, shorter canonical runtime, deleted confirmed dead tests, or newly protected critical behaviour. Do not optimise raw test count or percentage coverage without a risk-based reason.
