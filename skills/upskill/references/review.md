# Review Skills

A review produces findings. Changes go through the core's *Change a skill*, straight away when the user asked to review and fix.

## Gather evidence

Real use beats reading. Where transcripts exist, find sessions that loaded the skill (search the transcript folders for its `SKILL.md` path) and sample a few recent ones: what the user asked, how many turns and how much context the run took, what it produced, and where the user corrected it, repeated themselves or asked "is this done?". Transcripts can hold personal data; read only what the question needs. Then read the skill against what you saw.

For the whole library, count how often each skill and file is loaded, and measure what a typical session loads in total.

## What to look for

In order of harm to real work:

1. **Harm:** instructions that can damage data, production, repositories or decisions; that act beyond the authority the user expects; or that conflict with the user's global instructions.
2. **Drag:** steps, reviews, confirmations, records, splits or handoffs that do not pay for themselves on a typical run; process that scales up by default rather than on a stated condition.
3. **Unclear output:** reports that run long, repeat themselves, narrate the process, or bury what the user must do.
4. **Bloat:** anything that fails the writing standard, such as restated common sense, duplication across files, abstract language or history.
5. **Routing:** descriptions that miss natural requests or catch a neighbour's; hidden prerequisites such as "load X first".
6. **Gaps:** a recurring failure in transcripts that nothing addresses.

Across the library, also look for skills with overlapping jobs, chains where one skill always hands to another (candidates to merge), and skills that are never used. Rare use is not proof of no value, so ask before removing a skill.

## Report

Lead with the few findings that matter most. For each: what goes wrong in practice (cite the transcript or the line), the cause, and the fix, which is usually a deletion or a replacement. Say plainly when a skill is fine. No scorecards.
